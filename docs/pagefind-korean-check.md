# Pagefind 한국어 검색 검증 결과 (WBS 6)

검증일: 2026-10-30
환경: Pagefind 1.5.2 extended, Chromium (Playwright 1.64.1 headless)
재현: `uv run python scripts/check_pagefind.py`

테스트 데이터 가이드의 한국어 문장 17개를 페이지 하나씩으로 만들어 색인하고, 실제 브라우저에서 Pagefind 공식 검색 코드로 검색어 21개를 검색했습니다. 보조 색인 방식 4가지를 같은 조건으로 비교했습니다.

## 비교한 방식

| 이름 | 문서에 추가로 색인하는 것 | 검색어 처리 |
| --- | --- | --- |
| none | 없음 (Pagefind 그대로) | 그대로 |
| a | 한글 단어의 2글자 조각(bigram) | 그대로 |
| b | a와 같음 | 3글자 이상 한글 검색어를 2글자 조각으로 나눔 |
| c | 한글 단어의 모든 접미사 + 이웃한 두 단어를 붙인 형태와 그 접미사 | 그대로 |
| d | b + 이웃한 두 단어를 붙인 형태의 2글자 조각 | b와 같음 |

조각은 낮은 가중치(`data-pagefind-weight="0.1"`)로 넣어 원래 단어 일치가 위에 오게 했습니다.

## 해석

- **Pagefind 그대로(none)도 단어 앞부분 일치는 잘 됩니다.** "회의"로 회의를, 회의실, 회의록을 찾습니다. 못 찾는 것은 단어 중간·끝의 말과 띄어쓰기 차이입니다.
- **d가 46개를 모두 찾았습니다.** b의 유일한 누락("발표자료"로 "발표 자료" 찾기)을 이웃 단어를 붙인 조각이 메웠습니다.
- **d의 기대 밖 결과 2건은 사실상 맞는 결과입니다.** "주회의"로 "이번 주 회의", "지난주 회의록"이 나왔는데, 띄어 쓴 "주 회의"이므로 사용자가 찾던 것일 가능성이 높습니다. 기대 목록을 좁게 잡아서 생긴 숫자입니다.
- **c는 생각보다 나빴습니다.** 단어 길이 상한(12글자) 때문에 긴 띄어쓰기 없는 문장 뒷부분("검색", "되는지")의 접미사가 만들어지지 않았습니다. 상한을 없애면 긴 문장에서 조각 수가 길이의 제곱으로 늘어납니다.
- **검색어를 나누는 방식(b, d)이 "없는 합성어"에 엉뚱한 결과를 내지 않았습니다.** 조각이 모두 있어야 결과가 나오기 때문입니다. 반면 none과 a는 Pagefind가 검색어를 나눠 일부만 맞는 결과를 보여 줬습니다.
- **색인 크기 차이는 이 표본에서는 의미가 없습니다.** 문장 17개라서 Pagefind 기본 파일이 대부분을 차지합니다. 실제 크기 영향은 3주차에 더 큰 데이터로 측정해야 합니다.

## 결론 (제안)

**Pagefind + d 방식(문서 bigram + 이웃 단어 붙인 bigram + 검색어 bigram 분해)을 제안합니다.**

3주차 뷰어 작업에 반영할 것:

- 빌드 시 메시지마다 bigram 조각을 낮은 가중치의 숨은 요소로 함께 색인
- 뷰어 검색창에서 3글자 이상 한글 검색어를 2글자 조각으로 나눈 뒤 Pagefind에 전달
- 검색 결과 미리보기는 Pagefind excerpt 대신 메시지 원문(meta)을 표시해 조각 텍스트가 보이지 않게 함
- 실제 규모 데이터(수만 건)로 색인 크기와 검색 속도 측정
