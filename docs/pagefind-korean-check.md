# Pagefind 한국어 검색 검증 결과

검증일: 2026-10-30
환경: Pagefind 1.5.2 extended, Chromium (Playwright 1.64.1 headless), Windows 11
재현: `uv run python scripts/check_pagefind.py --suite all --size 5000`
테스트 데이터: [scripts/search_cases.py](../scripts/search_cases.py)

보조 색인 방식 7가지를 두 종류의 테스트로 같은 조건에서 비교했습니다.

- **손으로 고른 케이스 (curated)**: 문장 45개, 검색어 31개. 조사·활용, 붙여 쓰기·띄어 쓰기, 한영 혼용, 숫자, 자음만 있는 글자(ㅋㅋ), 이모지·기호, 긴 메시지, 그리고 **오답 함정**(사회의, 국회의원, 기회의처럼 "회의"가 글자로는 들어 있지만 뜻이 다른 말)을 넣었습니다.
- **자동 생성 대량 케이스 (generated)**: 단어 10개 × 조사 × 띄어쓰기 형태 × 문장 틀로 만든 메시지 5,000개, 검색어 26개. 정답은 만드는 과정에서 정해집니다(시드 고정).

## 비교한 방식

| 이름 | 문서에 추가로 색인하는 것 | 검색어 처리 |
| --- | --- | --- |
| none | 없음 (Pagefind 그대로) | 그대로 |
| a | 한글 단어의 2글자 조각(bigram) | 그대로 |
| b | a와 같음 | 3글자 이상 한글 검색어를 2글자 조각으로 나눔 |
| c | 한글 단어의 모든 접미사(단어당 최대 12글자) + 이웃한 두 단어를 붙인 형태와 그 접미사 | 그대로 |
| d | b + 이웃한 두 단어를 붙인 형태의 2글자 조각 | b와 같음 |
| e | d와 같고, 자음·모음만 있는 글자(ㅋㅋ, ㅇㅋ)도 한글로 처리 | e 기준으로 나눔 |
| **f** | e와 같고, 영문·숫자와 한글이 만나는 곳에서 단어를 나눔 (API문서 → API, 문서) | f 기준으로 나눔 |

조각은 낮은 가중치(`data-pagefind-weight="0.1"`)로 넣어 원래 단어 일치가 위에 오게 했습니다.

## 해석

1. **f가 두 테스트 모두에서 재현율 100%입니다.** 손으로 고른 케이스 79개, 자동 생성 7,769개를 모두 찾았습니다.
2. **d의 숨은 버그를 찾았습니다.** d는 검색어를 나눌 때 완성형 한글만 알아봐서, "ㅋㅋ"는 빈 검색어가 되어 아무것도 못 찾고, "회의ㄱㄱ"는 "회의"로 바뀌어 엉뚱한 결과 16개를 냈습니다. e에서 자음·모음을 한글로 처리해 고쳤습니다. **검색어를 가공하는 방식은 알아보지 못한 글자를 버리면 안 된다**는 교훈입니다.
3. **한영 혼용("API문서")은 f에서만 해결됩니다.** 영문과 한글이 붙은 단어를 나누지 않으면 띄어 쓴 "API 문서"와 연결되지 않습니다.
4. **부분 일치의 대가: 오답 함정 3개는 모든 보조 색인 방식이 걸립니다.** "회의"로 검색하면 사회의, 국회의원, 기회의도 나옵니다. 글자로는 실제로 "회의"가 들어 있어서, 형태소 분석 없이는 피할 수 없습니다. Pagefind 그대로(none)만 걸리지 않지만, 대신 다음주회의, 회의🔥 같은 진짜 정답도 놓칩니다. **메신저 검색에서는 몇 개 더 나오는 것이 못 찾는 것보다 낫다**고 판단합니다. 원래 단어 일치가 위에 오도록 가중치를 낮췄으므로 함정 결과는 아래에 표시됩니다.
5. **비용은 감당할 만합니다 (5,000개 기준).** f는 none보다 색인이 17%, 검색 26번에 받은 색인이 48% 늘고, 검색 시간은 중앙값 7 ms입니다. c는 색인이 33%, 받은 색인이 112% 늘어 가장 무겁습니다.
6. **이 규모에서는 Pagefind의 조각 단위 로딩이 아직 드러나지 않습니다.** 5,000개 메시지에서도 모든 방식이 색인 파일 6개만 받았습니다. 메시지가 훨씬 많아지면 색인이 여러 조각으로 나뉘고 검색어에 필요한 조각만 받게 됩니다. 3주차에 수만 건 규모로 다시 측정합니다.

## 결론 (제안)

**Pagefind + f 방식을 제안합니다.**

3주차 뷰어 작업에 반영할 것:

- 빌드할 때 메시지마다 f 방식 조각(단어 bigram + 이웃 단어 붙인 bigram, 자음·모음 포함, 영문·한글 경계에서 분리)을 낮은 가중치의 숨은 요소로 함께 색인합니다.
- 뷰어 검색창에서 같은 규칙으로 3글자 이상 한글 검색어를 2글자 조각으로 나눈 뒤 Pagefind에 넘깁니다. 색인과 검색어 처리 규칙이 어긋나지 않게 테스트 케이스를 공유합니다.
- 검색 결과 미리보기는 Pagefind excerpt 대신 메시지 원문(meta)을 표시해 조각 텍스트가 보이지 않게 합니다.
- 수만 건 규모로 색인 크기, 받은 색인 양, 검색 속도를 다시 측정합니다.
